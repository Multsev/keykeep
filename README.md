# KeyKeep

Компактный офлайн-менеджер паролей для Android и macOS. Данные остаются на устройстве, а при необходимости синхронизируются как зашифрованная база KeePass (`.kdbx`) через Яндекс Диск.

> Проект находится в разработке. Не используйте отладочно подписанные APK для хранилища единственных копий важных паролей: всегда держите отдельную проверенную резервную копию KDBX.

## Разработка версии на Rust

В ветке `rust-android-macos` обе платформы используют ядро из `rust/core` и интерфейс из `native/ui`. Оболочки в `native/macos` и `native/android` отвечают за окна, системные ключи, биометрию и выбор файлов. Прежний Android-клиент находится в `lib/`. Его возможности описаны ниже.

Ход проверки по 72 сценариям исходного приложения приведён в [таблице приёмки](docs/Проверка-переноса.md).

Для сборки на Apple Silicon нужны Rust, Xcode с командными инструментами и macOS 14 или новее. Для Android установите JDK 17, Android SDK Platform 35, Build Tools 35.0.0 и NDK 28.2.13676358. Android-скрипт использует локальный отладочный ключ `~/.android/debug.keystore`. Путь к SDK, NDK и JDK можно задать через `ANDROID_HOME`, `ANDROID_NDK_HOME` и `JAVA_HOME`.

```sh
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
./scripts/build-rust-macos.sh
open target/macos/KeyKeep.app
rustup target add aarch64-linux-android
./scripts/build-rust-android.sh
adb -s SERIAL install -r target/android/KeyKeep.apk
```

Для локальных обновлений macOS сборщик использует сертификат Apple Development. Если сертификатов несколько, задайте отпечаток нужного через переменную `KEYKEEP_MAC_SIGN_IDENTITY`. Используйте тот же сертификат для следующих сборок, чтобы Связка ключей узнавала KeyKeep. Тестовые сборки изолированы от личных хранилищ.

Замените `SERIAL` на идентификатор тестового устройства из `adb devices`. APK рассчитан на arm64, минимальная версия Android 9. Для обновления прежнего приложения требуются одинаковая подпись и совместимый номер версии. Значение для сборки можно задать через `KEYKEEP_VERSION_CODE`. До проверки обновления на своём устройстве сохраните отдельную рабочую копию KDBX. Android-клиент читает прежние настройки Flutter Secure Storage 10.3.1 с параметрами по умолчанию при первом вводе прежнего PIN.

В карточке записи можно выбрать папку, скопировать логин или пароль, добавить текстовое поле, защищённое поле или TOTP-секрет в формате Base32. Код действует до конца текущего 30-секундного интервала. При сохранении изменений прежние значения попадают в раздел «История изменений». Чтобы увидеть прежний пароль, раскройте версию и нажмите «Показать». На Android для переименования, переноса и удаления папки выберите её и нажмите «Изменить папку» над списком записей. Перед удалением приложение показывает число вложенных папок и записей. Поиск из любой папки охватывает всё хранилище и показывает путь к найденной записи. После удаления отдельной записи кнопка «Отменить удаление» доступна 30 секунд до блокировки. Она возвращает запись в исходную папку вместе с историей.

Чтобы включить вход по отпечатку, откройте «Настройки», введите текущий PIN и нажмите «Включить» в разделе «Вход по отпечатку». После системного подтверждения при открытии приложения появится запрос отпечатка. Снимите флажок «Запрашивать отпечаток при открытии», если предпочитаете вызывать его кнопкой. После отмены запроса можно сразу ввести PIN.

На Mac выберите базу в панели «Хранилища» слева и введите её мастер-PIN справа. После входа панель сворачивается. Кнопка «Хранилища» в верхней строке открывает и скрывает список. Путь внизу окна открывается по нажатию: Finder выделит файл текущей базы. Флажок «Запомнить вход до блокировки» оставляет выбранную базу открытой в памяти при переключении. Можно отметить несколько баз. Команда «Заблокировать», скрытие или сворачивание окна, блокировка Mac и выход закрывают все сеансы. Для создания нажмите «+» в панели. В стандартном окне macOS выберите папку, например «Загрузки», укажите имя файла .kk и задайте PIN. В пустом списке нажмите «Создать хранилище», выберите имя файла и папку, затем задайте PIN. Чтобы вернуть удалённую базу, нажмите ↶ рядом с заголовком «Хранилища» и выберите её имя. Чтобы переместить базу в Корзину Mac, нажмите значок корзины справа от её имени и подтвердите удаление. Правый клик по строке открывает команды удаления и переименования в списке. Правый клик по пустому месту панели открывает команду создания базы. Прежняя локальная база называется «Основное».

Для просмотра текущего PIN откройте «Настройки» и нажмите «Посмотреть PIN». На Android 9 и 10 система запросит код, пароль или графический ключ блокировки устройства. После подтверждения KeyKeep покажет PIN в отдельном окне на 10 секунд. Хранилище в это время уже заблокировано. При отмене откроется экран входа.

Для повторной проверки на Android 9 и 10 используются отдельные эмуляторы `keykeep-qa-api28` и `keykeep-qa-api29`. Установите в них тестовый системный PIN `772255` и Rust APK. Запустите `scripts/test-android-migration.sh SERIAL --legacy-pin` для каждого эмулятора. Тест создаёт собственное хранилище при первом запуске.

Команда **Настройки → Удалить локальное хранилище** требует текущий PIN и отдельное подтверждение. Она удаляет локальную базу, снимки перед импортом и восстановлением, учётные данные интеграций и ключи входа. После прерывания подтверждённого удаления приложение завершает его при следующем запуске. Отдельно экспортированные KDBX и файлы на Яндекс Диске сохраняются. За физическую очистку ячеек флеш-памяти отвечает устройство.

При создании хранилища и смене мастер-PIN можно указать от одного символа. Для PIN короче шести символов под полем появляется подсказка «Слабый PIN».

После четвёртой ошибки ввода PIN приложение вводит паузу от пяти секунд. При дальнейших ошибках пауза растёт до пяти минут и сохраняется при перезапуске.

Для переноса записей между платформами откройте **Настройки → Обмен с KeePass**. На исходном устройстве введите пароль базы и выберите формат экспорта. По умолчанию выбран KDBX 4, для старых клиентов доступен KDBX 3. Затем нажмите «Экспортировать». На новом устройстве раскройте «Импортировать базу KeePass» на первом экране, выберите файл, введите его пароль и дважды введите новый локальный PIN. Нажмите «Импортировать и открыть». Если хранилище уже создано, импорт доступен в настройках с подтверждением замены записей. При наличии ключевого файла выберите тот же файл на обоих устройствах. На Android после системного выбора файла может потребоваться повторный вход по PIN. Выбранный файл останется доступен в настройках до завершения операции. Перед импортом приложение сохраняет предыдущую зашифрованную базу рядом с рабочей в файле `vault.before-import.kk`.

Для проверки первого импорта используйте отдельный чистый профиль эмулятора Android 12 с установленной Rust-сборкой. Запустите `KEEPASSXC_CLI=/path/to/keepassxc-cli scripts/test-android-migration.sh SERIAL --first-import`. Тест создаёт базу KeePassXC с тестовой записью и выбирает файл в системном диалоге Android. Он проверяет отмену, неверный пароль, повторную попытку и открытие по новому PIN. В профиле останется тестовое хранилище.

Общие настройки на Mac занимают всё окно и открываются без мастер-PIN. Секция «Инструменты» раскрывает команды из ответа MCP tools/list, их назначение и параметры. Раздел «MCP-сервер» показывает состояние сервера, активную базу, число авторизованных JSON-RPC запросов с момента запуска и имя клиента из последнего запроса initialize. Уведомления без идентификатора в счётчик не входят. Включение сохраняется между запусками. При блокировке сервер останавливается, при открытии базы запускается в режиме чтения. Кнопка «Скопировать команду для Codex» доступна сразу после открытия хранилища, в том числе до запуска сервера.

На Mac откройте шестерёнку в шапке окна или нажмите ⌘,. Общие настройки доступны до создания базы и до ввода PIN. Укажите публичный Client ID, нажмите «Подключить» и подтвердите доступ в браузере. KeyKeep хранит общее подключение в Связке ключей Mac. Для открытой базы выберите «Настройки хранилища → Яндекс Диск», включите синхронизацию, укажите отдельную папку и сохраните выбор. Новые хранилища создаются с выключенной синхронизацией.

На Android для ручной синхронизации откройте **Настройки → Яндекс Диск**. Укажите публичный Client ID и имя папки. В настройках OAuth-приложения Яндекса должен быть зарегистрирован адрес возврата `keykeep://oauth/callback`. Нажмите «Подключить» и подтвердите доступ в системном браузере. Если Android заблокировал хранилище при переключении в браузер, после возврата введите PIN. Токен, состояние запроса и проверочный код PKCE сохраняются внутри зашифрованного локального хранилища. Экспорт KDBX включает только записи и папки.

Нажмите «Проверить версии», сравните даты локальной и облачной баз, введите пароль KDBX и подтвердите выбранное действие. «На Диск» сохраняет снимок предыдущей облачной базы и отправляет новую версию. «Восстановить на устройстве» позволяет выбрать текущую базу или снимок из истории. KeyKeep проверяет пароль загруженной базы и сохраняет локальный снимок до замены данных. Если с последней синхронизации изменились обе базы, KeyKeep предупредит об этом. Кнопка «Объединить» сохраняет уникальные записи обеих сторон. Для одной и той же записи основной становится версия с более поздней датой изменения, а при одинаковых датах сохраняется локальная версия. Вторая версия остаётся в истории. После объединения KeyKeep записывает результат на Диск и на устройство.

Если передача прервалась, KeyKeep сохраняет подтверждённую к отправке копию KDBX на устройстве. При следующем входе он повторит отправку этой копии. Её также можно отправить или отменить в настройках. Если облачная база успела измениться, повторная отправка остановится и потребуется снова проверить версии.

Ядро читает и записывает KDBX 3 и 4. Вложенные группы, защищённые поля, порядок пользовательских полей и история KeyKeep переносятся. Импорт записей с вложениями останавливается с сообщением. Для проверки двустороннего обмена с KeePassXC и проверки macOS-интерфейса на синтетических данных выполните:

```sh
KEEPASSXC_CLI=/path/to/keepassxc-cli cargo test --release --test kdbx -- --include-ignored
./scripts/build-rust-macos.sh --ui-test
target/ui-test/KeyKeepTest.app/Contents/MacOS/KeyKeep
```

В Rust-клиенте откройте **Настройки → Доступ через MCP** и нажмите «Включить MCP». Скопируйте команду подключения и выполните её на компьютере с клиентом Codex. На Android предварительно соедините устройство по USB и выполните `adb -s SERIAL forward tcp:8766 tcp:8766`. Оба приложения слушают адрес `127.0.0.1:8766`. На macOS клиент подключается напрямую.

Клиент может получить список названий, логинов и папок. Для чтения полной записи KeyKeep показывает название и спрашивает разрешение. Создание и изменение требуют включённой настройки записи и отдельного подтверждения. Запрос действует 30 секунд. Блокировка закрывает порт и отменяет ожидающие запросы. Команда «Сменить токен» завершает текущий сеанс. После неё скопируйте новую команду подключения.

Для проверки совместимости с официальным Python SDK MCP укажите интерпретатор с установленным пакетом `mcp` версии 1.x и выполните `MCP_PYTHON=/path/to/python cargo test --release official_client -- --ignored`. Тест создаёт временное пустое хранилище, подключает клиент и проверяет доступные инструменты.

Для проверки биометрии на тестовом Android-эмуляторе API 31 используйте профиль с перенесённой тестовой записью MigrationFixture. Зарегистрируйте в системных настройках виртуальный отпечаток № 1 и выполните `scripts/test-android-migration.sh SERIAL --fingerprint`. Тест включает вход по отпечатку, проверяет автоматический запрос, ручной вход, показ PIN после системного подтверждения, отмену и возврат к PIN. В конце он отключает биометрию в тестовом приложении.

Для проверки на физическом Mac соберите отдельное тестовое приложение и запустите его из терминала. Приготовьтесь подтвердить включение Touch ID, вход и просмотр тестового PIN в системных диалогах.

```sh
./scripts/build-rust-macos.sh --touch-id-test
target/ui-test/KeyKeepTouchIDTest.app/Contents/MacOS/KeyKeep
```

Проверка создаёт временное хранилище и использует отдельные настройки. При успехе появится строка `PASS Touch ID`. Для проверки только доступности датчика и запуска тестового приложения задайте `KEYKEEP_TOUCH_PREFLIGHT=1`.

## Что умеет

- классическое дерево папок и подпапок;
- записи с логином, паролем, заметками и произвольными полями, включая защищённые;
- генератор паролей и локальный TOTP-код по Base32-секрету;
- история изменений записи и прежних паролей;
- импорт и экспорт KDBX 3.x/4.x, совместимый с KeePass и KeePassXC;
- мастер-PIN и вход по биометрии устройства;
- OAuth-подключение к Яндекс Диску, ручная загрузка и восстановление KDBX;
- снимки версий на Диске до загрузки и восстановления;
- локальный MCP-сервер для ИИ — выключен по умолчанию, защищён токеном и требует подтверждения на телефоне для защищённых полей и записи.

## Как устроена безопасность

KeyKeep не содержит аналитики, рекламы или серверного аккаунта. Обычные записи сохраняются локально через Android Keystore-backed storage; системное резервное копирование приложения отключено. Экспорт и синхронизация передают на Диск только KDBX, зашифрованный паролем базы.

Мастер-PIN не сохраняется в исходном виде: для проверки используется соль и производное значение. Биометрический вход можно включить только после явного подтверждения пользователя.

Не добавляйте в issue, логи или pull request пароли, TOTP-секреты, OAuth-токены, `client secret`, файлы `.env`, `.kdbx`, `.jks` или `.keystore`. О проблемах безопасности — в [SECURITY.md](SECURITY.md).

## Быстрый запуск

Нужны Flutter SDK и Android SDK.

```bash
flutter pub get
flutter analyze
flutter test
flutter run
```

Для установки на свой телефон без подключения к IDE:

```bash
flutter build apk --debug
```

APK появится в `build/app/outputs/flutter-apk/app-debug.apk`. Разрешите установку из источника, через который передаёте APK, в настройках Android.

При первом запуске можно либо создать пустое хранилище, либо нажать «Импортировать KeePass (.kdbx)». Для импорта нужны пароль выбранной базы и новый мастер-PIN KeyKeep, который будет защищать её локальную копию.

## Яндекс Диск

В приложении откройте `Настройки → Интеграции → Яндекс Диск`, нажмите «Подключить Яндекс Диск», подтвердите вход в браузере и выберите обычную папку. В ней создаётся `keykeep-vault.kdbx` — его можно открыть также в KeePass на компьютере.

Для OAuth нужен только публичный Client ID Яндекс-приложения. Его можно передать при сборке, не добавляя в код:

```bash
flutter run --dart-define=YANDEX_OAUTH_CLIENT_ID=ваш_client_id
```

`client secret` в мобильное приложение не встраивается и никогда не нужен KeyKeep.

Перед восстановлением KeyKeep показывает дату локальной и облачной версий, предупреждает о замене и сохраняет локальный снимок. Перед загрузкой также сохраняется снимок текущей облачной базы. При изменениях на двух устройствах можно выбрать локальную версию, восстановить облачную или явно подтвердить объединение.

## MCP в прежнем Flutter-клиенте

Откройте `Настройки → Интеграции → MCP для ИИ` только на разблокированном устройстве. Сервер работает в локальной сети, останавливается при блокировке или уходе приложения в фон и требует bearer-токен. Не передавайте этот токен третьим лицам. Получение пароля/защищённого поля и каждая операция записи подтверждаются на телефоне.

## Сборка релиза для сопровождающего

Release-pipeline проверяет код, отправляет `main` в GitHub, собирает APK в GitHub Actions, публикует его в [GitHub Releases](https://github.com/Multsev/keykeep/releases) и скачивает тот же файл в неотслеживаемую папку `Release/`. Локально и в GitHub остаются только четыре последних успешных APK. Формат версии: `0.DDMMYY.NN`.

Для OAuth-синхронизации пользователей с Яндекс Диском в GitHub Actions Variable `YANDEX_OAUTH_CLIENT_ID` хранится публичный Client ID. Токен владельца Яндекс Диска для выпуска APK больше не нужен. Полная инструкция по настройке — в [docs/RELEASING.md](docs/RELEASING.md).

```bash
./scripts/release.sh
```

Текущий pipeline использует debug-подпись только для личного тестирования. Перед публичной раздачей APK нужно настроить отдельный production-ключ, хранимый в GitHub Secrets.

## Структура проекта

- `lib/domain` — модели записей и папок;
- `lib/data` — локальное защищённое хранилище;
- `lib/services` — KDBX, биометрия, TOTP, OAuth, синхронизация и MCP;
- `lib/ui` — интерфейс приложения;
- `test` — модульные тесты;
- `scripts` — сборка и выпуск APK.
