# KeyKeep

Офлайн-менеджер паролей для Android, созданный на Flutter/Dart и Material 3 — в том же стеке, что ProjectPulse.

## Возможности

- создание и проверка мастер-PIN без хранения самого PIN;
- хранение записей в Android Keystore через `flutter_secure_storage`;
- классическое дерево папок: открытие подпапок, хлебные крошки и отдельный список записей текущей папки;
- текстовые и защищённые пользовательские поля;
- импорт и экспорт совместимых KeePass KDBX 3.x/4.x баз;
- генератор стойких паролей;
- автоматическая блокировка при потере приложением фокуса.
- OAuth-подключение и ручная синхронизация зашифрованной KDBX-базы с Яндекс Диском;
- история смены каждого пароля с точным временем изменения.
- разблокирование по отпечатку пальца или биометрии устройства после явного включения;
- защищённое поле TOTP: текущий шестизначный код рассчитывается локально из Base32-секрета;
- вложенное дерево папок, сохраняемое при импорте, экспорте и синхронизации KDBX;
- неизменяемые зашифрованные снимки на Яндекс Диске с content-addressed ID версии.
- локальный MCP-сервер для доступа ИИ к структуре и записям по bearer-токену.

## Релиз на Яндекс Диск

1. Создайте Android keystore и OAuth-токен Яндекс Диска с доступом на запись.
2. Скопируйте `.env.example` в `.env` и заполните все переменные. Файл и keystore исключены из Git.
3. Убедитесь, что Git-дерево чистое, и выполните `./scripts/release.sh patch`.

Каждый Git-коммит запускает единый pipeline через `.githooks/post-commit`: анализ, тесты, создание одного **подписанного** release APK, публикация и Git-тег. Для активации hook один раз выполните `git config core.hooksPath .githooks`. Команда `./scripts/release.sh` повторно публикует текущий commit, если это необходимо.

Версия всегда имеет вид `0.DDMMYY` по московскому времени: например, `0.250826`. Пока продукт не вышел в production, ведущая цифра остаётся `0`. Если за день выпускается несколько сборок, у APK и Git-тега добавляется технический суффикс `b01`, `b02`; Android получает возрастающий build number `YYMMDDNN`. Пользовательская версия при этом не меняется.

Для ручного запуска используйте `./scripts/build_artifact.sh`. Он создаёт один подписанный `arm64-v8a` APK в исключённой из Git папке `Release/`; это архитектура большинства современных телефонов. Имя содержит только пользовательскую версию, например `KeyKeep-v0.250826.apk`. Перед публикацией pipeline очищает локальную папку `Release` и `KeyKeep/releases` на Яндекс Диске, поэтому в каждой из них остаётся ровно один актуальный APK. Чтобы включить копирование на NFS, задайте абсолютный путь уже смонтированного writable-каталога в `NFS_RELEASE_PATH`.

### Синхронизация в приложении

Создайте OAuth-приложение Яндекса с redirect URI `keykeep://oauth/callback`. В приложении откройте облачную синхронизацию, нажмите «Указать OAuth client ID», вставьте публичный client ID и затем «Подключить по OAuth». Client ID и выданный после входа access token хранятся в Android Keystore; client ID также можно передать при сборке через `YANDEX_OAUTH_CLIENT_ID`.

В разблокированном приложении нажмите значок облака, подключите Яндекс Диск и используйте загрузку/скачивание. На Диск передаётся не локальный JSON, а KDBX, зашифрованная текущим мастер-PIN; текущая база хранится в приватной app-папке, и при каждой загрузке сохраняется отдельный зашифрованный снимок в `keykeep-history`. Снимок получает короткий SHA-256 ID — аналог идентификатора Git-коммита. Это не заменяет полноценный Git-сервер, но даёт неизменяемые версии базы без передачи незашифрованных паролей.

### Биометрия и TOTP

После входа по мастер-PIN откройте настройки (значок шестерёнки) и включите вход по биометрии. KeyKeep запрашивает системное подтверждение и сохраняет PIN только в Android Keystore-backed storage; без успешной биометрии приложение его не использует. В редакторе записи добавьте пользовательское поле типа `TOTP` и введите Base32-секрет: код генерируется локально и никогда не отправляется в сеть.

При первом создании хранилища подтверждение нового мастер-PIN сразу открывает пустое хранилище. Если на устройстве настроена биометрия, KeyKeep тут же предложит включить вход по отпечатку пальца или лицу; это можно отложить и включить позднее через меню `⋮`.

### Настройки и управление хранилищем

В разблокированном хранилище откройте значок шестерёнки. Экран настроек позволяет включить/отключить биометрию и выбрать, должна ли она автоматически запрашиваться при каждом открытии приложения. Там же можно открыть другое KDBX-хранилище (оно заменит локальные записи), экспортировать текущее или удалить локальное хранилище после подтверждения. Удаление не затрагивает ранее выгруженные зашифрованные базы на Яндекс Диске.

### MCP для ИИ

В разблокированном приложении нажмите значок микросхемы и запустите MCP. Экран покажет команду подключения для Codex и bearer‑токен. По умолчанию можно читать структуру и конкретные записи; включение «Разрешить редактирование» открывает инструмент создания и изменения записей. Сервер останавливается при блокировке хранилища или уходе приложения в фон, токен хранится только в Android Keystore и его можно обновить в том же экране.

MCP-инструменты: `list_vault_structure`, `get_password_entry` (раскрывает пароль) и `upsert_password_entry` (только в режиме редактирования). Подключайте только доверенного ИИ-клиента в той же частной сети.

## Структура

- `lib/main.dart` — запуск и тема приложения.
- `lib/domain` — модели записи, папки и пользовательского поля.
- `lib/data` — защищённое локальное хранилище.
- `lib/services` — проверка мастер-PIN, биометрия, TOTP, генератор, KDBX-кодек и синхронизация.
- `lib/services/password_mcp_controller.dart` — защищённый локальный MCP-сервер.
- `lib/ui` — экраны разблокировки, списка и редактирования.
- `scripts/release.sh` — выпуск подписанного APK и публикация на Яндекс Диск.

Мастер-PIN используется только для проверки доступа. Android Keystore шифрует сохранённые записи; резервное копирование приложения отключено в манифесте, чтобы ключи и данные не попадали в системный бэкап. При импорте и экспорте KDBX используется отдельный пароль базы KeePass, совместимый с KeePassXC и KeePass.
