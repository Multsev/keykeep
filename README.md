# KeyKeep

Компактный офлайн-менеджер паролей для Android. Данные остаются на устройстве, а при необходимости синхронизируются как зашифрованная база KeePass (`.kdbx`) через Яндекс Диск.

> Проект находится в разработке. Не используйте отладочно подписанные APK для хранилища единственных копий важных паролей: всегда держите отдельную проверенную резервную копию KDBX.

## Что умеет

- классическое дерево папок и подпапок;
- записи с логином, паролем, заметками и произвольными полями, включая защищённые;
- генератор паролей и локальный TOTP-код по Base32-секрету;
- история изменений записи и прежних паролей;
- импорт и экспорт KDBX 3.x/4.x, совместимый с KeePass и KeePassXC;
- мастер-PIN и вход по биометрии устройства;
- OAuth-подключение к Яндекс Диску, ручная загрузка и восстановление KDBX;
- снимки версий на Диске до загрузки и восстановления;
- локальный MCP-сервер для ИИ — выключен по умолчанию, защищён токеном и требует подтверждения на телефоне для защищённых полей и записи.

## Как устроена безопасность

KeyKeep не содержит аналитики, рекламы или серверного аккаунта. Обычные записи сохраняются локально через Android Keystore-backed storage; системное резервное копирование приложения отключено. Экспорт и синхронизация передают на Диск только KDBX, зашифрованный паролем базы.

Мастер-PIN не сохраняется в исходном виде: для проверки используется соль и производное значение. Биометрический вход можно включить только после явного подтверждения пользователя.

Не добавляйте в issue, логи или pull request пароли, TOTP-секреты, OAuth-токены, `client secret`, файлы `.env`, `.kdbx`, `.jks` или `.keystore`. О проблемах безопасности — в [SECURITY.md](SECURITY.md).

## Быстрый запуск

Нужны Flutter SDK и Android SDK.

```bash
flutter pub get
flutter analyze
flutter test
flutter run
```

Для установки на свой телефон без подключения к IDE:

```bash
flutter build apk --debug
```

APK появится в `build/app/outputs/flutter-apk/app-debug.apk`. Разрешите установку из источника, через который передаёте APK, в настройках Android.

## Яндекс Диск

В приложении откройте `Настройки → Интеграции → Яндекс Диск`, нажмите «Подключить Яндекс Диск», подтвердите вход в браузере и выберите обычную папку. В ней создаётся `keykeep-vault.kdbx` — его можно открыть также в KeePass на компьютере.

Для OAuth нужен только публичный Client ID Яндекс-приложения. Его можно передать при сборке, не добавляя в код:

```bash
flutter run --dart-define=YANDEX_OAUTH_CLIENT_ID=ваш_client_id
```

`client secret` в мобильное приложение не встраивается и никогда не нужен KeyKeep.

Перед восстановлением KeyKeep показывает дату локальной и облачной версий, предупреждает о замене и сохраняет локальный снимок. Перед загрузкой также сохраняется снимок текущей облачной базы. При изменении одной и той же записи на двух устройствах KeyKeep не пытается незаметно объединить пароли: выберите нужную версию из истории и перенесите конфликтующие изменения осознанно.

## MCP для ИИ

Откройте `Настройки → Интеграции → MCP для ИИ` только на разблокированном устройстве. Сервер работает в локальной сети, останавливается при блокировке или уходе приложения в фон и требует bearer-токен. Не передавайте этот токен третьим лицам. Получение пароля/защищённого поля и каждая операция записи подтверждаются на телефоне.

## Сборка релиза для сопровождающего

Локальный pipeline создаёт APK в неотслеживаемой папке `Release/` и, если задан токен сопровождающего, копирует тот же APK в папку приложения на Яндекс Диске. Он сохраняет только четыре последних успешных APK. Формат версии: `0.DDMMYY.NN`.

Скопируйте `.env.example` в `.env` и заполните только нужные параметры. Полное описание переменных, подписи production-сборки и процесса выпуска — в [docs/RELEASING.md](docs/RELEASING.md).

```bash
./scripts/release.sh
```

Текущий pipeline использует debug-подпись только для личного тестирования. Перед публичной раздачей APK нужно настроить отдельный production-ключ, хранимый вне Git.

## Структура проекта

- `lib/domain` — модели записей и папок;
- `lib/data` — локальное защищённое хранилище;
- `lib/services` — KDBX, биометрия, TOTP, OAuth, синхронизация и MCP;
- `lib/ui` — интерфейс приложения;
- `test` — модульные тесты;
- `scripts` — сборка и выпуск APK.
